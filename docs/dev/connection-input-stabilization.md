# 연결·입력 안정화 1차 변경

2026-09-12 · 브랜치 `fix/connection-input-reliability`

이 문서는 1차 변경 시점의 기록입니다. 이후 보안 변경은 [2차 페어링·암호화](secure-pairing.md)에 정리합니다.

## 반영 범위

- 수락된 TCP 연결을 핸드셰이크 전부터 보관하고, 연결 수·대기 시간을 제한합니다. 현재 연결 외의 제어 명령과 이전 연결의 지연 콜백을 거부합니다.
- TCP 분할·연속 프레임, 마지막 데이터와 EOF가 함께 오는 경우, 비정상 헤더·길이를 처리합니다. UDP 수신을 첫 데이터그램 이후에도 계속합니다.
- UDP에 매 연결별 HMAC 키와 시퀀스를 도입해 서명 없는 패킷, 변조, 중복·과거 패킷을 거부합니다. 이전 세션의 콜백도 구분합니다.
- 마우스 클릭을 TCP로 보내고, 이동 좌표·드래그 이벤트를 수정합니다. 연결 해제와 서버 중지 시 누른 키·버튼을 해제합니다.
- emoji·결합문자 전체 UTF-16을 전송하고, 네트워크에서 받은 숫자의 범위를 확인해 변환 중 충돌을 방지합니다.
- macOS 페어링 코드 창, 취소·만료 처리를 연결하고 PIN을 로그에서 제거합니다.
- 재연결의 스트림·배처 수명, 네트워크 감시 재시작, 저전력 설정 재진입, 마지막 트랙패드 이동 처리 문제를 보완합니다.
- 저장소의 비동기 barrier 쓰기를 잠금 기반의 즉시 반영으로 변경해 읽기 순서와 동시 테스트 문제를 줄입니다.
- 화면 좌표를 Accessibility 좌표로 변환해 창 정렬의 세로 위치를 보정합니다.

기존 작업 트리의 앱·설정 변경은 함께 유지했습니다. 아직 커밋·푸시하지 않았습니다.

## 빌드 호환성

Xcode 26.5 / Tuist 4.71.0에서 확인했습니다. 앱·공유 모듈은 Swift 6을 유지하며, TCA 1.23.1만 기본 패키지 manifest가 지원하는 Swift 5 언어 모드로 컴파일합니다. swift-collections 1.3.0의 누락된 lifetime 옵션을 보완하면서 기존 availability 매크로를 유지합니다. 의존성 업데이트 시 이 우회 설정을 재평가해야 합니다.

AppTests에는 `IssueReportingTestSupport`를 명시적으로 연결합니다. 지원 모듈 없이 Swift Testing 내부 ABI를 추측하는 경로는 현재 테스트 런타임에서 충돌했습니다.

프로젝트 설정은 `tuist generate --no-open`으로 재생성하며, Xcode에서는 저장소 루트의 `Snap.xcworkspace`를 사용합니다.

## 검증 범위와 후속 작업

- iOS 시뮬레이터: AppTests 119개 통과 (iPhone 17 / iOS 26.5).
- 공유 모듈·macOS 입력: 67개 테스트 통과.
- MacReceiver Debug 빌드 성공, SwiftLint 경고 0개, `git diff --check` 통과.
- 코드 서명 없이 개발 빌드·테스트를 검증했습니다. 배포용 Archive는 검증하지 않았습니다.

공유 모듈과 macOS 입력 코드는 별도 SwiftPM 테스트 하네스로 검증했습니다. 루프백 TCP/UDP 통신은 실제 소켓을 사용하며, 입력 테스트는 이벤트를 캡처해 실제 키보드·마우스를 조작하지 않습니다. iPhone과 Mac 두 실기기의 페어링, 접근성 권한, 절전 복귀, 다중 화면 체감 동작은 별도 확인이 필요합니다.

프로토콜 v2는 두 앱을 함께 업데이트해야 합니다. [현재 wire format](../design/ProtocolSpec.md)을 참고하세요.

이 단계는 암호화 완료가 아닙니다. TCP가 기본 평문이며, 기존 신뢰 기기는 여전히 기기 ID로 판정합니다. 인증서 신뢰 검증·안전한 키 교환·TLS 기본 활성화가 다음 우선순위입니다. IME 편집, 음성 전송, 위젯 명령 연결, iCloud 연동도 후속 범위입니다.

사용자 승인 후 [GitHub #151](https://github.com/unib35/Snap/issues/151)에 등록했습니다.

Xcode에서 번들이 누락됐던 추가 로그는 외부 의존성 없이 App·Shared·SnapWidget 3개 타깃만 빌드한 상태였습니다. 워크스페이스를 사용해야 TCA와 swift-sharing 리소스 번들 생성 타깃이 빌드 그래프에 포함됩니다.
