# Claude Commands 가이드

이 문서는 Snap 프로젝트에서 사용할 수 있는 Claude Code custom commands를 설명합니다.
모든 명령어는 Kent Beck의 TDD 및 Tidy First 원칙을 따릅니다.

## 명령어 목록

### TDD 명령어

| 명령어        | 인자             | 설명                                          |
| ------------- | ---------------- | --------------------------------------------- |
| `/tdd-plan`   | 기능 설명        | 테스트 계획을 작성하고 `plan.md` 생성         |
| `/tdd-status` | -                | 현재 TDD 진행 상황 (완료/남은 테스트, 진행률) |
| `/tdd-go`     | -                | 다음 테스트 구현 (Red → Green 사이클)         |
| `/tdd-test`   | 타겟 (선택)      | 테스트 실행 및 결과 분석                      |
| `/tdd-verify` | -                | 커밋 전 전체 검증 (build, test)               |
| `/tdd-commit` | 메시지 (선택)    | TDD 원칙에 맞는 커밋 수행                     |

### 프로젝트 명령어

| 명령어         | 인자              | 설명                                    |
| -------------- | ----------------- | --------------------------------------- |
| `/dev-check`   | -                 | 프로젝트 상태 확인 (git, 빌드, 의존성)  |
| `/dev-setup`   | `reset` (선택)    | 개발 환경 설정 및 진단                  |
| `/feature-new` | feature 이름      | 새 기능 브랜치 생성                     |
| `/issue-create`| 이슈 설명         | GitHub 이슈 생성                        |
| `/pr-create`   | 대상 브랜치 (선택)| TDD 체크리스트 포함 PR 생성             |

## 워크플로우

### 1. 새 기능 개발 (Feature Development)

새로운 기능을 TDD로 개발하는 전체 흐름입니다.

```
┌─────────────────────────────────────────────────────────────┐
│  1. 기능 시작                                                │
│     /feature-new trackpad-gesture                           │
│     → feat/trackpad-gesture 브랜치 생성                     │
├─────────────────────────────────────────────────────────────┤
│  2. 계획 수립                                                │
│     /tdd-plan 트랙패드 제스처 인식 기능                      │
│     → plan.md 생성                                          │
├─────────────────────────────────────────────────────────────┤
│  3. 개발 사이클 (반복)                                       │
│     ┌──────────────────────────────────────────────────┐    │
│     │  /tdd-status    → 진행 상황 확인                  │    │
│     │  /tdd-go        → Red → Green 구현               │    │
│     │  /tdd-test      → 테스트 통과 확인                │    │
│     └──────────────────────────────────────────────────┘    │
├─────────────────────────────────────────────────────────────┤
│  4. 커밋                                                     │
│     /tdd-verify       → 전체 검증                           │
│     /tdd-commit       → 커밋 수행                           │
├─────────────────────────────────────────────────────────────┤
│  5. PR 생성                                                  │
│     /pr-create        → Pull Request 생성                   │
└─────────────────────────────────────────────────────────────┘
```

#### 실제 사용 예시

```bash
# 1. 새 기능 브랜치 시작
/feature-new socket-connection

# 2. 기능 계획
/tdd-plan iOS ↔ macOS 소켓 연결 - TCP/UDP 통신 구현

# 3. 진행 상황 확인
/tdd-status
# 📊 TDD 진행 상황
# ✅ 완료: 0개 | ⏳ 남음: 5개 | 📈 진행률: 0%
# 🎯 다음: shouldConnectToServerSuccessfully

# 4. 테스트 구현
/tdd-go
# Red → Green 사이클 자동 수행

# 5. 반복...
/tdd-status  # 진행률 확인
/tdd-go      # 다음 테스트

# 6. 커밋 전 검증
/tdd-verify

# 7. 커밋
/tdd-commit

# 8. PR 생성
/pr-create
```

### 2. 버그 수정 (Bug Fix)

```
┌─────────────────────────────────────────────────────────────┐
│  1. 버그 재현 테스트 작성                                    │
│     - 실패하는 테스트 먼저 작성                              │
│     - 버그가 재현되는 최소 테스트                            │
├─────────────────────────────────────────────────────────────┤
│  2. 버그 수정                                                │
│     - 테스트가 통과하도록 수정                               │
├─────────────────────────────────────────────────────────────┤
│  3. 검증 및 커밋                                             │
│     /tdd-verify                                              │
│     /tdd-commit                                              │
└─────────────────────────────────────────────────────────────┘
```

---

### 3. 개발 환경 관리

```bash
# 프로젝트 상태 한눈에 확인
/dev-check

# 개발 환경 초기 설정 또는 문제 진단
/dev-setup

# 클린 설치가 필요할 때
/dev-setup reset
```

## 커밋 컨벤션

TDD commands는 다음 커밋 메시지 형식을 사용합니다:

| 접두어       | 용도                      | 예시                                          |
| ------------ | ------------------------- | --------------------------------------------- |
| `[Feat]`     | 새 기능 (행위적 변경)     | `[Feat]: 트랙패드 제스처 인식 구현`           |
| `[Fix]`      | 버그 수정                 | `[Fix]: 연결 끊김 시 재연결 실패 해결`        |
| `[Refactor]` | 리팩토링 (구조적 변경)    | `[Refactor]: NetworkClient 프로토콜 분리`     |
| `[Test]`     | 테스트 추가               | `[Test]: DiscoveryClient 유닛 테스트 추가`    |
| `[Setting]`  | 프로젝트 설정             | `[Setting]: Tuist 의존성 업데이트`            |
| `[Docs]`     | 문서 작업                 | `[Docs]: README 설치 가이드 추가`             |

## 주의사항

### TDD 사이클 준수

```
Red → Green → Refactor
 │      │         │
 │      │         └─ 테스트 통과 상태에서만
 │      └─ 최소한의 코드만
 └─ 먼저 실패하는 테스트
```

### 커밋 분리 (Tidy First)

```
❌ 잘못된 예: 리팩토링 + 새 기능을 하나의 커밋에

✅ 올바른 예:
   1. [Refactor]: 기존 코드 정리
   2. [Feat]: 새 기능 추가
```

### Tuist 명령어

```bash
# 의존성 설치
tuist install

# 프로젝트 생성
tuist generate

# 빌드
tuist build App
tuist build MacReceiver

# 테스트
tuist test
```
