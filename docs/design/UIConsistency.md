# UI 일관성 기준

2026-09-13 · [GitHub #153](https://github.com/unib35/Snap/issues/153)

## 시각적 기준

기본 화면은 중립적인 시스템 배경과 하나의 강조색을 사용한다. 강조색 기본값은 파란색이며 기존 설정에서 고른 색상도 화면 전체에 전달한다. 특정 기능을 구분하기 위해 화면마다 별도의 네온 팔레트를 만들지 않는다.

| 역할 | 기준 |
| --- | --- |
| 화면 배경 | 시스템 grouped/window background |
| 카드·시트 표면 | 시스템 elevated/control background |
| 입력·버튼 표면 | 시스템 fill 계층 |
| 주요/보조 텍스트 | 시스템 primary/secondary |
| 선택·일반 액션·연결 진행 | 앱 강조색 |
| 연결 완료 | 초록 + 상태 아이콘·문구 |
| 일반 연결 해제 | 중립 회색 + 연결 안내 |
| 오류·삭제·녹음 | 의미에 맞는 빨강 |
| 권한 주의·경고 | 주황 + 아이콘·설명 |

색상은 Shared의 `SnapPalette`에서 정의한다. iOS는 `SnapColors` 별칭으로 같은 정의를 사용하고, macOS도 상태 색상을 공유한다. 화면에서 고정 RGB 값을 추가하는 대신 의미에 맞는 토큰을 선택한다. 라이트·다크 모드는 시스템 설정을 따른다.

매크로와 바로가기는 중립 표면에 사용자 지정 아이콘 색상을 표시한다. 분류 색상과 앱 브랜드 색상, 실제 레이저의 빨강은 의미가 있으므로 유지한다. 발표·숏폼 전체화면은 기존의 어두운 제어 화면을 유지하고 해당 화면의 색상 환경도 다크로 맞춘다. QR에는 스캔을 위한 흰 바탕을 유지한다.

## 컴포넌트

- 섹션 카드: `cardStyle()`의 공통 배경과 16pt 모서리. 화면별로 배경 투명도를 달리하지 않는다.
- 설정·목록·메뉴·탭·툴바: 플랫폼 표준 컨트롤을 사용한다.
- 온보딩·연결 안내·유틸리티 액션: `SnapActionButtonStyle`, 최소 높이 48pt, 12pt 모서리. 눌림·비활성 상태와 동작 줄이기를 지원한다.
- 글꼴: `SnapTypography`의 시스템 TextStyle을 사용한다. 제목에만 둥근 서체를 혼합하던 설정을 정리했다.
- 화면 제목: 현재 탭 이름. 상태 색상은 아이콘에 표시하고 상태바 배경은 중립 표면으로 유지한다.
- 연결 전 화면: 입력 영역을 비활성화하고 공통 안내와 **Mac 연결** 버튼을 제공한다.

## 검증

- iOS 앱의 기존 테스트 121개와 임시 화면 렌더링 하네스 1개 통과.
- 트랙패드·키보드·미디어·더보기·설정·페어링·온보딩·연결 전 화면의 라이트/다크 16개, 큰 글자 설정 1개, 보라색 강조색 1개를 렌더링했다.
- 렌더링은 iOS 26.5 시뮬레이터에서 실제 SwiftUI 뷰와 상태를 사용했다. 빈 reducer를 사용해 Mac 연결이나 입력을 실행하지 않았다.
- 최종 iOS 및 MacReceiver Debug 빌드, SwiftLint, `git diff --check`를 확인했다.
- 검토용 이미지는 이번 작업의 HTML 미리보기에 보존했다. 임시 렌더링 테스트는 앱 테스트 타깃에서 제거했다.

컴퓨터 조작 도구의 권한이 승인되지 않아 직접 터치 탐색과 macOS 화면 캡처는 하지 못했다. 모든 세부 화면·iPad 배치·VoiceOver의 실기기 탐색까지 검증한 것은 아니다. 기존 기능·보안 변경은 유지했으며 커밋·푸시는 하지 않았다.

## 참고

Apple은 고정 색보다 시스템 의미 색상을 사용해 외관 변화에 대응하고, 버튼 높이·모서리·안쪽 여백의 일관성을 유지하도록 안내한다.

## 실사용 중심 화면 구조 · 2026-09-15

일상적인 트랙패드·키보드 조작을 기본 사용 흐름으로 삼았다. 주요 탭은 고정하고 각 탭에 별도 NavigationStack을 배치해 도구 상세 화면에서 다른 탭으로 이동해도 탐색 위치를 유지한다.

- **트랙패드:** 표준 입력 모드 선택, 넓은 터치 영역, 명시적인 왼쪽/오른쪽 클릭, 열린 창 보기와 제스처 사용법. 상시 파동 애니메이션과 대형 워터마크, 권한 설명 없이 비활성화되던 음성 버튼을 제거했다. 음성 입력은 도구에서 권한 안내와 함께 제공한다.
- **키보드:** 입력 → 조합 키 → 특수 키 → 방향 키 순서로 묶는다. 입력이 즉시 전송됨을 설명하고, 전체 조합 키 해제와 시스템 키보드 닫기를 제공한다. 입력 표시 지우기는 Mac의 텍스트를 지우지 않는다는 접근성 안내를 포함한다.
- **미디어:** 재생과 Mac 볼륨을 분리하고 기기 볼륨 버튼 설정은 DisclosureGroup으로 접어 둔다. 볼륨 수치와 충분한 터치 영역을 제공한다.
- **도구:** 기존 8개 패널을 동시에 펼치지 않는다. Mac 작업 / 발표와 콘텐츠 / 음성 목록에서 선택하면 해당 도구만 표시한다. 실제로 빈 텍스트만 보내던 받아쓰기 버튼은 제거하고, 음성 입력 화면으로 경로를 통합했다.
- **연결:** 중복 상태바를 제거하고 상단의 Mac 이름으로 연결 상태와 관리 화면에 접근한다. 연결 완료 전에는 원격 입력 화면을 표시하지 않는다. 연결 화면에서 현재 Mac, 해제, 연결 취소, 재연결 중지, 재검색, 오류 안내를 제공한다.
- **접근성:** 클릭 버튼과 조합 키에 VoiceOver 액션을 추가했다. 스크롤 가능한 조작 화면과 시스템 텍스트 스타일을 사용한다.

[Apple의 탐색 설계 가이드](https://developer.apple.com/videos/play/wwdc2022/10001/)에 따라 탭은 주요 화면 이동, NavigationStack은 각 화면 안의 계층 탐색에 사용한다.

### 이번 변경의 검증 범위

- 기존 App 테스트 121개 및 임시 렌더링 테스트 1개 통과 (`/tmp/snap-usable-tests-retry.log`).
- 기본 4개 탭과 연결·설정 등 28개 화면을 렌더링했다. 라이트/다크, 320pt 폭의 작은 화면, 접근성 1 크기의 글자를 포함한다.
- 고정된 상태와 빈 reducer로 실제 SwiftUI를 렌더링했다. 스크롤 화면의 이미지는 최초 표시 영역이며, 실제 Mac 입력이나 손가락 제스처를 실행한 결과는 아니다.
- 기본 탐색과 개별 도구 진입은 코드로 검토했다. VoiceOver 실기기 탐색, 시스템 키보드를 연 상태의 입력, iPad 전용 배치는 별도 사용 검증이 필요하다.
- 초기 테스트는 시뮬레이터가 이전 앱 실행을 종료하지 못해 중단했다. 해당 테스트/앱을 종료하고 시뮬레이터 재시작 후 전체 테스트가 통과했다.
- 최종 보완 후 렌더링 테스트 재통과 (`/tmp/snap-usable-render-final.log`). 임시 하네스를 제거하고 프로젝트 재생성 후 arm64/x86_64 시뮬레이터 앱 빌드 통과 (`/tmp/snap-usable-build-final.log`).
- SwiftLint 위반 및 `git diff --check` 오류 없음. 변경은 작업 디렉터리에 반영했으며 커밋·푸시하지 않았다.

## 트랙패드·레이저 조작 일관성 · 2026-09-16

- 두 모드에서 동일한 `clickButtons`와 `ClickButton`을 사용한다. 클릭 문구, 버튼 높이·글꼴·색상·눌림 효과·접근성 안내를 한 곳에서 정의한다.
- 레이저의 별도 `LaserClickButton` 구현을 제거했다. 클릭 누름/해제 액션은 유지한다.
- 레이저 작동 방식을 표준 segmented picker의 “누르는 동안 / 켜기·끄기”로 안내한다. 영문 내부 값 대신 기존 표시 이름을 사용한다.
- 영문 활성화 안내와 반복 발광 효과를 제거하고, 시작·멈춤과 감도를 한국어로 설명한다. 활성 상태에는 레이저의 의미 색상만 사용한다.
- 클릭 버튼을 제어 영역의 스크롤 밖에 배치했다. 작은 화면과 큰 글자에서도 클릭 버튼을 바로 조작할 수 있다.
- 사용법 시트는 선택된 입력 모드에 맞는 내용을 표시한다.

검증: 클릭 버튼·모드 전환의 기존 테스트 7개와 임시 렌더링 1개 통과. 라이트/다크의 두 입력 모드 및 작은 화면·큰 글자의 레이저 화면 6개를 확인했다. 작은 화면에서 제어 버튼이 온전히 표시되도록 보완 후 렌더링도 재통과했다. 임시 하네스는 제거했다. 실제 Mac의 자이로 조작은 이번 렌더링 검증에 포함하지 않았다.
최종 arm64/x86_64 시뮬레이터 앱 빌드, SwiftLint 및 `git diff --check`도 통과했다.
